DECISOES VIGENTES
- ADR-001 (Aceito) monólito single-process, sem auth, bind 127.0.0.1 — restrição: nenhuma etapa (publish/prospect inclusive) pode expor porta/rede ou pedir auth própria; integrações externas rodam server-side na mesma instância.
- ADR-002 (Aceito) Higgsfield somente via CLI oficial (`studio/higgsfield.py`, subprocess + `--json`); nunca `api.higgsfield.ai`, nunca automatizar UI; IDs de modelo não fixados em código — consultar catálogo vivo; "modo UI + importar" é o caminho legítimo para o ilimitado do plano. Restrição: base/storyboard/shots/animate/music/export usam `hf.generate`/`hf.cost`/import de Downloads/histórico, nada mais.
- ADR-003 (Aceita) persistência em FS sob `PROJECT_LAYOUT` (`studio/config.py`), sem banco — restrição: artefatos novos vão em `projects/<id>/<pasta>` (as pastas `assets, images, videos, audio, edit, export, jobs` já são criadas em `create_project`).
- ADR-004 (Aceito) fidelidade ao roteiro: a etapa produz só o que a aula produz; extensões marcadas `[extensão]` e só com aprovação; desvio técnico = ADR + nota na etapa. Restrição: itens do plano marcados [INFERÊNCIA] (character sheet, shotlist com gramática de cinema, color match, hook 3 s, end card, `brain_activity`, `reframe`) NÃO entram sem aprovação.
- ADR-005 (Aceito) Pinterest via Playwright — não afeta a wave.
- ADR-006 (Aceita) jobs em threads daemon + estado em memória + polling; um job por projeto por serviço — restrição: sem Celery/fila, sem WebSocket; seguir o padrão `_jobs/_lock`.
- ADR-007 (Aceito) mood = 1 prompt de vibe, teto de 8 selecionadas, sem produto/pessoas — restrição: a etapa 3 (base) consome `mood/selected/` + `palette.json` e é ela quem põe o produto na cena.
- ADR-008 (Aceito) testes sem rede/navegador com fakes; CI ruff+pytest; trailer `Task-Id` obrigatório em todo commit (hook `.githooks` + job `task-id-check`); branch `<tipo>/<id-kebab>-<desc>` a partir de `develop`, PR para `develop`.
