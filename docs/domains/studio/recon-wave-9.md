## TERRENO

- Monólito FastAPI single-process, sem banco, SPA vanilla; etapas são plugins `studio/etapas/<id>/` (META+router+view.html+view.js); núcleo (`app.py`, `steps.py`, `web/*`) só editável por frente de preparo/shell (`docs/domains/studio/hld.md:63-73`). Jobs longos = thread + `JobRegistry` + polling `GET .../job`; persistência = JSON+imagens em `projects/<pid>/`, escrita atômica (tmp+`os.replace`; `common/atomic.write_json_atomic` em `settings.py:87-90`).
- Prompter (`studio/common/prompter.py`): "bot" via Claude CLI local (`BIN=which("claude")` :19, `MODEL` env :21). `ROLES` :117-139 tem só `mood`/`base`/`motion` — **não existe papel "script"**. Contrato: `from_brief(kind,brief)` :193, `from_images(kind,images,instruction,brief)` :200 (máx 4 imagens, `--allowedTools Read`), `fallback_template` :244 quando o CLI falta, saída `{prompt,negative,camera,notes_pt,source,seconds}` (`_parse` :170). `PROMPT_FORMAT`/`EXAMPLE_PROMPT` fixam a estrutura "parágrafo + 5 linhas Camera/Lighting/Composition/Color grading/Style" — `split_sections`/`provenance` :65-103 e o FDD base-prompt-provenance dependem desse formato. `STYLE_VARIANTS` :223-228 é o precedente de "presets" (mood importa de lá, `studio/mood/service.py:56`).
- Settings (ADR-016, `studio/common/settings.py`): `ACTIONS` :32-56 (chaves `base.image`, `storyboard.scene`, `storyboard.video.*`…), `DEFAULTS` :61-75, resolução projeto→global→código em `default_for` :143; livro-caixa `record_generation` :212 após cada geração real. Hoje o settings resolve **modelo por ação**, não presets arbitrários — preset de realismo por ação é conceito novo a encaixar nesse padrão.
- Storyboard (`studio/storyboard/service.py`): docstring :12 diz explicitamente "O que a aula não ensina fica de fora: **nada de roteiro por LLM**" — a feature 1 contradiz esse texto e precisa de rótulo `[extensão]`+ADR. `scenes.json` = `{id,n,text,images[],primary,videos[],photos{}}` (ADR-018/022; `_normalize` :410, `save_scenes` :458 regrava `storyboard.md` junto :459). Geração paga: `_cli_request`/`start_generate` :552-612 mandam `{"prompt", "image_references":[src]}` ao `hf.generate` — `image_references` já é lista (ponto de anexo do inpaint-marcação). `video_prompt` :736 já usa `prompter.from_images("motion",…)` — precedente de LLM na etapa 4. Ângulos (`angles.py`): `start_generate` :455 aceita `image_references` extra :462; `build_prompts` :285 monta câmera/lente (`_camera` :274) — é onde "rig presets" já meio existem.
- Base (`studio/base/service.py`): `KINDS=("situation","label","upscale")` :38 com `RANK` :39, `DEFAULT_COUNT` :59, `_check_kind` :486, `_plan` :641-678 (branch por kind; `label` usa a situação selecionada + `label_prompt` :343), `_default_model` :474 via settings. `kind="clean"` entra como 4º branch nesses pontos + `_normalize`/`chain`/`most_advanced` (:520-538) e no router (`studio/etapas/base/router.py:130-199`, param `kind`).
- Refs (`studio/refs/`): busca por termos via Playwright (`pinterest.py:102-165`, perfil persistente `_launch` :47, ritmo humano, dedupe por SHA-1; `_download` :168-207 reutilizável — baixa via `ctx.request.get` com fallback de tamanhos e cria `Candidate{source,term,url,pin_url,…}`). Serviço: `start_search` :202 (job em `_jobs` dict próprio, não JobRegistry), `import_upload` :271 (`[extensão]`, `source="upload"`). Rotas em `studio/etapas/refs/router.py:53-95`.
- Ingest transversal (`studio/common/ingest.py`): `ingest_bytes` :64-111 (sha12, thumbs, dedupe, `meta` livre — `role`/`parent` do multishot entram por aqui) e `import_upload/downloads/history` :114-151. Multishot (`common/multishot.py`, ADR-017): núcleo agnóstico de dono; `_params` :48 usa `image_references=[source]`.
- UI: `Studio.ui.confirmCost` (`web/ui.js:158-172`, modo rico ADR-016 consulta custo no servidor), `progressJob` :471; etapa 4 `view.js` (1022 linhas) em 2 blocos (`:31` ideação/cenas, `:702` ângulos), vídeo por cena :341-513, `confirmCost` :480.

## DECISÕES VIGENTES

- ADR-002 (Higgsfield só via CLI oficial; nunca `api.higgsfield.ai` nem automação da UI) — inpaint-marcacao e base-clean só podem gerar via `hf.generate`; edição "localizada" vira instrução por prompt + imagem anotada como referência (não há máscara real no CLI).
- ADR-004 + gates do CLAUDE.md (fidelidade ao curso) — roteiro por LLM, presets de realismo, inpaint por rabisco, kind clean e import por URL são todos `[extensão]`: aprovação do dono + marca `[extensão]` na UI/código; desvio de método = ADR nova. Atenção: storyboard/service.py:12 hoje **nega** roteiro LLM na etapa 4.
- ADR-005 (scraping Pinterest via Playwright, sessão do usuário, ritmo humano, teto por termo) — refs-import-url deve seguir o mesmo padrão (mesmo perfil `_launch`, pausas, dedupe), sem virar crawler agressivo de boards.
- ADR-010 (núcleo só preparo/shell; guia por leitura pura) — as 5 features editam apenas plugin+serviço; nada em `app.py`/`steps.py`/`web/*` (se prompter-presets precisar de UI transversal em `web/ui.js`, isso é frente de preparo/shell).
- ADR-016 (modelo default por ação via settings; custo antes de gerar; livro-caixa depois) — presets de realismo "por ação via settings" estendem `ACTIONS`/`DEFAULTS`/`default_for`; hoje o schema só tem `{model,variant}` — preset é campo novo no override (aditivo, com fallback p/ configs antigas). Toda geração nova (clean, inpaint) passa por `cost`+`confirmCost` e registra `record_generation`.
- ADR-015 (ângulos fundidos na etapa 4), ADR-018/021/022/023 (galeria de keyframes com `primary`; vídeo por cena kling2_6 / transição kling3_0; mapa `photos` retrocompat) — storyboard-roteiro-llm só pré-preenche `text` das cenas; não pode reestruturar `scenes.json`.
- ADR-017 (multishot agnóstico de dono) e ADR-020 (marca validada em `refs/validated_brand.json` como fonte única) — base-clean-marca deve reusar `brand_get`/`_brand_from_disk` (`base/service.py:182,681`), não criar outra fonte de marca.
- ADR-006/003/008 — jobs em thread+polling; estado só em arquivo; testes sem rede/navegador (fakes: `tests/test_prompter.py` monkeypatcha `BIN`/`subprocess.run`; Playwright nunca roda em teste).
- ADR-024 é o último número; próximo sequencial livre = ADR-025 (ADR-030 existe fora de sequência; `docs/adrs/mapping.md` vai até 023+024).

## CONTRATOS EXISTENTES

- Feature 1 (roteiro LLM): `GET/PUT /api/projects/{pid}/storyboard/scenes` (router :178-183; PUT regrava md), `GET /api/projects/{pid}/storyboard` :119, `POST .../storyboard/video-prompt` :211 (precedente de rota de prompt LLM). Novo endpoint de roteiro deve ser aditivo; scenes.json existente nunca sobrescrito sem ação do usuário (é "sugestão editável").
- Feature 2 (presets): `studio/etapas/*/router.py` de custo/generate que leem `settings.default_for`; painel "Créditos & Custos" consome `all_defaults` (`settings.py:178`). Rotas de config global/projeto já existem via tela de custos (checar `studio/etapas/` plugin de custos antes de criar rota nova).
- Feature 3 (inpaint): `POST /api/projects/{pid}/storyboard/cost` :194 e `/generate` :199 (body kind/text/count/source_id → `_cli_request` monta `image_references:[src]`, service :552-605); ângulos: `POST .../angles/scenes/{scene}/generate` :391 já aceita `image_references` extras (`angles.py:455-473`). Upload da imagem anotada pode reusar `ingest_bytes` com `meta={"role":"annotation",…}`.
- Feature 4 (clean): `POST /api/projects/{pid}/base/generate` :178, `/cost` :166, `/import/*` :130-154, `/select` :199 — todos parametrizados por `kind`; erro atual de kind inválido cita "situation, label ou upscale" (`_check_kind` :488, atualizar mensagem+testes). Cadeia `chain`/`RANK`/`most_advanced` e `base_final.png` definem qual imagem alimenta o upscale — decidir onde "clean" entra no RANK.
- Feature 5 (import URL): `POST /api/projects/{pid}/refs/search` :63 (terms), `GET .../refs/job` :71, `.../candidates` :77, `POST .../import/upload` :82, `.../select` :95. Novo `import/url` deve devolver `Candidate` no mesmo schema (`pinterest.Candidate` :28: id, source, term, url, pin_url, alt, file, thumb, w, h) para a tela/seleção existentes funcionarem sem mudança.

## LACUNAS E DESATUALIZAÇÕES

- Não há FDD para nenhuma das 5 features; storyboard não tem HLD (só `prd.md` + FDDs); refs/mood/base têm HLD não relidos nesta recon (código+ADRs lidos); mood não é tocado diretamente pelas features exceto via prompter compartilhado.
- A skill `/generate_realistic_prompt_images` (briefing de diretor de fotografia, rig presets, aberturas) não existe no repo — é insumo externo em `~/.claude/skills/generate_realistic_prompt_images/` (SKILL.md + reference.md); sua lógica precisa ser transcrita para `prompter.py` (papel novo + presets) sem quebrar `PROMPT_FORMAT`/`provenance`.
- `settings.py` não tem conceito de preset nomeado nem de parâmetro além de model/variant — schema de config precisa de extensão desenhada (retrocompat com `config.json` existentes).
- Não há canvas/annotation em lugar nenhum da SPA (grep sem ocorrências); `ingest` não tem kind para imagem "derivada/anotada" — anotação entraria como arquivo comum.
- `refs` usa job dict próprio (`_jobs`, `service.py:202-246`), não o `JobRegistry` comum — import por URL deve seguir o padrão local do domínio, não misturar.
- Nano Banana via CLI não tem máscara: "editar só a área marcada" é best-effort por prompt — limite a deixar explícito no FDD/UI (não prometer inpaint real).

## ATENÇÃO PARA ESTE TRABALHO

- Tudo é aditivo: não renomear rotas, campos de `scenes.json`/`candidates.json`, chaves de `ACTIONS`/`DEFAULTS`, classes CSS do catálogo do shell, nem mensagens/strings fixadas em testes (`tests/test_api.py`, `test_prompter.py`, testes por etapa). Papel novo no prompter = chave nova em `ROLES`; kinds novos = valores novos, nunca troca dos existentes.
- Feature 1 exige ADR nova (contraria o texto de `storyboard/service.py:1-14` e o escopo da aula 010) e o pré-preenchimento deve ser opt-in, nunca sobrescrever `text` já digitado; entrevista de FDD pode pular "qual o schema de cena" (ADR-018/022 já respondem) e "qual modelo/rota de LLM" (Claude CLI via prompter, padrão do `video-prompt`).
- Feature 2: presets vivem em `settings.py` (padrão ADR-016: dado, não regra espalhada); "documentary street" como default de código em `DEFAULTS`-like, override projeto>global; nada de env var.
- Features 3/4: fluxo pago obrigatório = `cost` no servidor → `ui.confirmCost` → job com polling → `record_generation`; imagem anotada entra como referência EXTRA (a original continua primeira em `image_references`); ADR-002 proíbe qualquer caminho fora do CLI.
- Feature 5: reusar `_launch`/perfil/cookies e `_download` de `pinterest.py`; respeitar ritmo humano e teto (ADR-005); board = N pins com teto tipo `max_per_term`; job assíncrono como o search.
- Gitflow: branch de `develop`, trailer `Task-Id: ADH-OS-…`, gate ft-pr, `make verify`; worktrees paralelas com PORT ≥ 8766; docs/PR em pt-BR, prompts de geração em inglês.
