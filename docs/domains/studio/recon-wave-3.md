## 4. CONVENÇÕES DE `Studio.ui` / `app.js` que as telas dependem
- `renderGuide(stepId, el?)`: busca `/guide/{step}`, renderiza em `#guide` (ou `el`), chama `Studio.onGuide` (menu/topo/overview atualizam) e devolve o guia; sem pid escreve `div.empty` "Sem campanha selecionada — crie uma campanha…" (string testada). `ctx.guide()` = `renderGuide(currentStep)`. Telas chamam em `onProject()` e após cada ação que muda artefato.
- `chip(text, kind)` → `<span class="chip {kind}">`; kinds com CSS: `ok done warn fail blocked info in_progress todo unknown mode`.
- `hfChip(el)` reescreve `textContent` + `className = "chip ok|warn"` do span.
- `drop(el, onFiles)`: usa o `<input type=file>` interno do `label.drop` (ou cria oculto); alterna `.over`.
- `upload(url, files, field="files", extra={})`; `confirmCost(costFn, label)` usa `window.confirm` (README: inalterado).
- `poll(fn, ms)` → `{stop()}`; para com `false`, 3 erros ou `stop()`; todo plugin chama `stop()` em `destroy()` (smoke `--timers` cobra).
- `modal({title, subtitle, html, onClose})` → `{el, close}`; foco preso, Esc/backdrop fecham; quem chama liga botões por `el.querySelector`.
- app.js: `showView` injeta view.html em `#main`, carrega view.js **uma vez** (`loaded` Set — editar view.js exige reload da página), `ensureGuideSlot`, `factories[id](ctx).init()`, depois `renderGuide(id)`; `destroyCurrent()` antes de trocar e ao ir para overview; `#main.onclick` é zerado na troca (telas não devem depender dele). Hash: `navigate(target)` escreve `#/<pid>/<target>`; `Studio.go(id)` só navega para `overview` ou etapa `ready`.
- Tema: `aplicaTema("auto"|"light"|"dark")` → `document.documentElement.dataset.theme` (removido em auto) + `studio.theme`; index.html aplica antes do 1º paint. Tokens claros em `:root`, escuros em `@media(prefers-color-scheme:dark) :root:not([data-theme="light"])` e `:root[data-theme="dark"]` (duplicados — o redesign pode unificar via bloco repetido, mas as duas strings testadas têm de existir).
